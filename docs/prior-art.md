# Existing workflows and prior art

No new graph algorithm or first clock synchronization workflow is claimed. The prospective value of ClockWeave is its deliberately bounded OTLP/Jaeger qualification, explicit domain/epoch aggregation, global constant-model diagnosis and independently replayable evidence.

- [Trace Compass](https://archive.eclipse.org/tracecompass/doc/stable/org.eclipse.tracecompass.doc.dev/Event-matching-and-trace-synchronization.html) supports custom application-event matching, pairwise convex-hull synchronization, constant/linear transforms and graph-path composition. Its [user workflow](https://archive.eclipse.org/tracecompass/doc/stable/org.eclipse.tracecompass.doc.user/Trace-synchronization.html) preserves originals and reports synchronization quality. It is a mature and broader mathematical workflow; application-event matching is not a ClockWeave novelty.
- [Jaeger](https://github.com/jaegertracing/jaeger/blob/main/cmd/jaeger/internal/extension/jaegerquery/internal/adjuster/clockskew.go) provides recursive clock-skew display adjustment, source identity handling, adjustable/disableable correction and warnings. The official runtime was exercised on the exact shared export view in this project's qualification. Successful corrections are credited; lack of ClockWeave's diagnostic schema is not a viewer failure.
- [Zipkin](https://github.com/openzipkin/zipkin/blob/master/zipkin-lens/src/zipkin/clock-skew.js) uses kind/endpoint information and recursive point corrections. Prefer an existing viewer when visual correction is the desired result. No Zipkin runtime head-to-head is claimed here.
- [Perfetto clock synchronization](https://perfetto.dev/docs/concepts/clock-sync) and [trace merging](https://perfetto.dev/docs/concepts/merging-traces) use recorded synchronization evidence and support multi-machine traces. Prefer measured calibration when available. ClockWeave does not replace that evidence.
- [distributed-tracing-correlator](https://github.com/sidhartha-patra/distributed-tracing-correlator) already states the constant-offset band equations and mentions Bellman-Ford. The core inequality idea is expressly prior art.
- Intel Trace Collector, TAU and Scalasca also provide substantial synchronization/correction workflows for collected/HPC traces. They are not absent alternatives.

[Jaeger issue #961](https://github.com/jaegertracing/jaeger/issues/961) is historical motivation for transparent correction and instrumentation-versus-clock ambiguity; transparency improvements already addressed it. It is not described as an unimplemented Jaeger feature. No production defect or universal superiority claim is made. Product adoption and willingness to author qualification contracts remain unproven.
